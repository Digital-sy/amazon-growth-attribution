# Amazon Growth Attribution V1.0 成果总结

> 状态：V1.0 阶段完结  
> 完结时间：2026-07-28  
> 下一阶段：取得稳定的 SKU/MSKU 级来源数据后，推进“款号 × 月份”归因分析。

## 1. 项目目标

本项目用于整合 Amazon 订单、广告、站内促销、站外推广和价格相关数据，建立可追溯、可复跑、可审计的订单来源分析体系。

V1.0 的核心目标不是构造一个无法验证的逐单精准归因模型，而是：

1. 建立 Amazon All Orders Report 的稳定入库能力；
2. 形成订单商品明细层的统一有效订单口径；
3. 按固定优先级生成互斥的五类订单来源；
4. 在“店铺 × 月份”层面输出来源结构、订单量、销量和销售额；
5. 建立广告统计分配审计，明确估算层级和数据限制；
6. 补充款号月度成交价，作为后续商品维度分析的基础。

## 2. V1.0 已完成范围

### 2.1 Amazon All Orders TXT 入库

已形成 Seller Central All Orders Report 的本地 TXT 导入流程，支持：

- UTF-8 BOM、制表符和动态表头识别；
- 按目标表实际字段动态映射；
- 文件名自动识别店铺和月份；
- 兼容未完结月份命名，例如 `RKZ2607-.txt`；
- 默认预检，正式写入需显式指定整月替换；
- 同一未完结月份重复导入时，先删除店铺当月旧数据，再事务写入最新月累计文件；
- 自动记录源文件 SHA-256、源行号和导入批次；
- 保留 Amazon 原始报告中的 `quantity=0` 记录，下游有效订单再过滤；
- 使用原始或合成 `order_item_id` 保障订单商品唯一性；
- 写入失败自动回滚，避免整月数据处于半完成状态。

核心脚本：

- `pipelines/orders/import_amazon_all_orders.py`
- `imports/import_amazon_orders_txt_monthly.py`
- `imports/import_amazon_orders_txt_monthly_v2.py`

### 2.2 有效订单基础层

统一有效订单口径包括：

- `sales_channel = 'Amazon.com'`
- `order_status = 'Shipped'`
- `item_status = 'Shipped'`
- `quantity > 0`
- `item_price > 0`
- `currency = 'USD'`
- SKU、购买时间非空

订单月份以 `purchase_date_utc` 从 UTC 转换为 `America/Los_Angeles` 后归属。

基础层保留：订单号、订单商品、店铺、SKU/MSKU、ASIN、数量、销售金额、促销折扣、促销标识、来源标签及规则版本等字段。

### 2.3 五类订单来源模型

V1.0 采用固定互斥优先级：

```text
站外推广 > 广告 > 站内促销 > 低价 > 自然
```

原则：

- 站外推广优先识别，避免同一订单被广告或站内促销重复占用；
- 广告订单在缺少 Amazon 订单号级归因数据时，采用可复现的统计分配；
- 站内促销根据促销字段和折扣特征识别；
- 低价在排除站外、广告和站内促销后识别；
- 剩余有效订单归为自然订单；
- 原始标签与最终互斥分类同时保留。

### 2.4 广告统计分配与审计

V1.0 已实现可复跑的广告订单统计分配流程，并保留：

- 分配目标；
- 候选订单；
- 已分配与未分配数量；
- 分配率；
- 分配层级；
- 置信度；
- 规则版本；
- 月度审计结果。

历史实现包括同日 SKU、同月 SKU、店铺月份兜底等分配层级，最终运行入口已切换到现有可用的产品表现月度来源。该结果用于“店铺 × 月份”的来源结构分析，不应被解释为 Amazon 官方提供的逐单精准归因。

### 2.5 数据表与运行能力

已建立并使用的核心结果层包括：

- `dwd_amz_order_attribution_base`：有效订单商品归因基础表；
- `dws_amz_ad_order_demand_daily`：广告订单统计需求；
- `dwd_amz_ad_order_allocation`：广告订单分配结果；
- `dwd_amz_order_attribution_result`：五类互斥归因结果；
- `dws_amz_order_source_monthly`：店铺月度五类汇总；
- 广告分配月度审计表。

运行能力包括：

- 按月份回填；
- 按店铺筛选；
- 可重启、可断点的历史回填；
- MySQL 长任务和超时优化；
- MSKU 大小写及排序规则兼容；
- 长时间运行时自动刷新领星 Token；
- 日志和审计结果输出。

### 2.6 五类来源月度 Excel

已完成五类订单来源的月度 Excel 导出，包含：

- 总览；
- 五类订单结构；
- 逐月占比；
- 店铺月度明细；
- 广告统计分配审计；
- 口径说明。

核心脚本位于 `reports/` 目录。

### 2.7 款号月度成交价

已完成订单、Listing 和产品管理快照的关联链路：

```text
订单 store_name + MSKU
→ Listing 店铺 + MSKU
→ Listing 本地 SKU + 当前负责人
→ 产品管理快照 SKU
→ SPU/款号 + 季节 + 品类
```

成交价口径：

```text
销量加权成交价
= SUM(item_price - item_promotion_discount) / SUM(quantity)
```

已支持：

- 2025-01 至 2026-07 的可配置月份范围；
- 款号月度长表；
- 款号月度宽表；
- 映射审计；
- 月份覆盖检查；
- 按店铺拆分为 `JQ-US`、`MT-US`、`RKZ-US`、`SY-US` 四张 Sheet；
- 7月未完结月累计数据导入后重新生成。

核心脚本：

- `reports/export_style_monthly_deal_price.py`
- `reports/export_style_monthly_deal_price_by_store.py`

## 4. V1.0 的明确边界

### 4.1 已可靠支持

- Amazon 订单原始数据入库与审计；
- 有效订单口径统一；
- 店铺 × 月份的五类订单来源结构；
- 来源订单量、销量、销售额和占比；
- 广告统计分配过程及审计；
- 款号 × 月份的销量加权成交价；
- Listing 当前负责人、季节和品类维度补充。

### 4.2 当前不能宣称

- Amazon 官方逐单广告归因；
- 历史月份真实负责人归属；
- SKU/款号层面的精准五类来源归因；
- 基于当前月度来源总量直接拆分出的款号来源结构具有官方准确性。

负责人来自当前 Listing 快照，因此只能用于当前组织维度展示，不能代表历史月份当时的负责人。

## 5. V2.0 推进条件与路线图

V2.0 的目标是从“店铺 × 月份”推进到“款号 × 月份”，但前提是取得稳定、可审计的 SKU/MSKU 级来源数据。

### 5.1 前置数据条件

至少需要获得以下一类或多类 SKU/MSKU 级数据：

- SKU/MSKU 级广告订单或广告销售；
- SKU/MSKU 级站外推广订单；
- SKU/MSKU 级站内促销订单；
- 可与订单商品明细稳定关联的来源标识；
- 来源数据的店铺、月份、SKU/MSKU统一键。

### 5.2 V2.0 目标模型

建议目标粒度：

```text
店铺 × 月份 × 款号 × 来源类型
```

目标指标：

- 订单-SKU数；
- 销量；
- 净商品销售额；
- 来源占比；
- 销量加权成交价；
- MSKU数和本地SKU数；
- 分配层级、置信度和数据完整率；
- 季节、品类、负责人等商品维度。

### 5.3 推荐推进顺序

1. 固化 SKU/MSKU 级来源数据采集表；
2. 建立店铺 + 月份 + SKU/MSKU 的统一键和质量审计；
3. 验证来源总量与店铺月度结果是否一致；
4. 关联 Listing、本地 SKU 和产品管理快照；
5. 生成款号 × 月份 × 来源类型结果表；
6. 建立未匹配、重复映射和分配差额审计；
7. 输出业务版 Excel 或 BI 看板；
8. 在数据稳定后再讨论负责人绩效和商品策略应用。

## 6. 版本结论

V1.0 已完成从原始订单入库到店铺月度来源结构输出的完整闭环，并补齐了款号月度成交价和商品维度映射基础。

项目当前可以作为稳定的 V1.0 基线使用。V2.0 不应继续通过扩大月度统计分配来强行生成款号归因，而应等待 SKU/MSKU 级来源数据具备后，再按“款号 × 月份”建立更细粒度、可验证的归因模型。
